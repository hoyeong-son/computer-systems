## 2.2.1. 정수형 데이터 타입

- C 에서 제공하는 정수형 타입의 크기는 아키텍쳐, OS에 따라 다르다.
- C 는 Data type의 크기가 강제되지 않는다.
	- C 언어 표준 기구는 type의 크기를 강제하지 않는 대신, 최소한의 가이드라인과 상대적인 크기 관계만을 정의했다.
		- `char <= short <= int <= long <= long long`
		- `1byte, 2byte, 2byte, 4byte, 8byte`
	- 수많은 기업과 단체(GNU, LLVM, MS, Intel)가 수많은 컴파일러를 만드는 과정에서 그것이 실행될 컴퓨터 환경(아키텍처, OS)에 따라 데이터 타입의 크기가 달라지게 됐다.
- Java(Oracle), C#(MS)은 거대 기업이 만든 '가상 머신 표준 명세서'가 중심이라 데이터 크기가 항상 일치한다.
- Rust, Go 등의 언어는 애초에 type의 이름으로 `i32` 와 같이 크기를 명시하며 공식 컴파일러의 지배력이 강하여 데이터 크기가 달라질 여지가 없다.

## 2.2.2. 비부호형 인코딩

$$B2U_w(x) = \sum_{i=0}^{w-1}x_i2^i$$

## 2.2.3. 2의 보수 인코딩

$$B2T_w(x) = -x_{w-1}2^{w-1} + \sum_{i=0}^{w-2}x_i2^i$$

- 음수는 2의 보수법에 따라 $-X$ 가 $2^w - X$ 로 저장돼있다.
- $B2T_w(x)$ 수식은 MSB가 1인 수에서 $2^w - X - 2^w$ 를 간단하게 수식화한 것이다.

## 2.2.4. 비부호형과 부호형 간의 변환

- 부호형과 비부호형 간의 캐스팅이 일어날 때, 메모리에 저장된 실제 비트 데이터는  변하지 않는다.
	- 비트의 해석만 달라진다.

## 2.2.6. 수의 비트 표시 확장

- **zero extension** : unsigned data를 더 큰 크기의 type으로 casting한다면 추가된 비트를 0으로 채우면 수를 유지하게 된다.

- signed data를 더 큰 크기의 type으로 casting
	- **sign extension** : MSB로 채우기
	- 저장된 값이 양수 혹은 0이라면 MSB인 0으로 채우면 유지된다.
	- 저장된 값이 음수 ($2^n - X$) 인 경우
		- n 비트 공간에서 n + k 비트 공간으로 비트 확장이 일어나면 2의 보수법에 따라 -X 의 표현이 $2^n - X$ 에서 $2^{n+k} - X$ 로 변한다.
		- 둘을 비교
			- $2^{n+k} - X - (2^n - X) = 2^n(2^k - 1)$
			- $2^k - 1$ 을 2진수로 표시하면 $11...11$($k$개) 가 되며 2를 곱하는 행위는 상위 비트로의 shift와 같다. $11...1100...00$($n$개의 0비트)
			- k 비트의 확장은 $11...11$($k$개)$00...00$($n$개) 를 기존 n비트 수에 더해주면
		- 따라서 음수인 경우 MSB인 1로 상위 k비트를 채우면 수가 유지되게 된다. (k개 비트를 1로 채움)

- 정수끼리의 type casting만 비트가 바뀌지 않음. 부동소수점으로의 casting 등은 비트를 바꾼다.

---

## 2.2.7. 수의 절삭

- 더 작은 type으로 casting은 상위 비트들을 통째로 절삭해버린다.
	- MSB 위치는 무시하고 그냥 절삭
- 수학적으로 이 절삭은 mod $2^n$와 같다.
	- 새로운 MSB 값은 수의 크기가 casting된 type의 범위 내일때 그대로 유지된다.
		- 확장의 역연산 (**2.2.6. 확장** 에서 상위 k 비트들이 절삭되는 것과 같다.)
	- 수의 크기가 범위를 벗어난다면 수의 표현에 쓰였던 상위 bit가 날아가고 남은 하위 비트들 중 하나가 이상한 MSB로 쓰인다. (수가 잘리며 부호도 왜곡)
