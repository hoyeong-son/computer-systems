# 2.1. 정보의 저장

## 가상 메모리

- 프로세스는 **가상 주소**(**Virtual Address**)를 사용한다.
	- 컴파일러는 이 프로그램이 실제 사용자의 RAM(물리 메모리) 몇 번지에 올려져서 실행될지 모른다.
	- 컴파일러는 "이 프로그램은 0x000... 번지부터 시작되는 독립된 공간을 통째로 쓴다"고 가정한 채 기계 코드를 작성한다.
	- 각 프로세스는 자기만의 독립된 **가상 주소공간**을 갖고, 물리 메모리 상태를 전혀 모른다.
	- CPU가 프로세스의 가상 주소를 참조하면, MMU(메모리 관리 장치)가 운영체제가 관리하는 페이지 테이블을 이용해 이를 물리 주소로 변환한다.
	- 가상 주소공간은 복잡한 물리 메모리와 달리 균일한 1차원 바이트 배열이다.
		- 물리 메모리는 matrix 구조, 채널 분할 등이 전혀 균일하지 않다.

## 2.1.1. 16진수

- cs에서 16진수가 선택된 이유는 인간을 위해서이다.
	- 4bit = 1 hex digit이라 변환이 자릿수 단위로 독립적이다. 반면 10진수는 비트 경계와 맞지 않아 불편함이 있다.
	- 1 byte = 2자리 hex
	- ex)
		- binary : 1111 1111 0000 0000
		- hex : 0xFF00
		- decimal : 65280
		- 16진수에서는 상위 바이트가 0xFF 라는 것이 직관적이지만 10진수에서는 보이지 않는다.
	- 8진수도 같은 원리로 주로 쓰였다.

## 2.1.2. 데이터의 크기

- 컴퓨터는 고유한 워드 크기를 가지며, 가상 주소 하나는 한 워드로 표현된다.
	- ex) 64bit 시스템에서 가상 주소는 0x000000000000F000 같이 부여된다.
		- 이론상 64bit 시스템은 가상 주소공간이 $2^{64}$개의 주소로 이루어지며 이는 16EB에 해당된다.
	- 워드 크기(word size) : cpu가 하나의 단위로 다루는 고정 길이 비트 묶음
		- 레지스터 크기, 포인터 크기가 일반적으로 워드 크기와 같다.
		- 주소를 담는 레지스터의 크기가 64bit이므로 포인터도 64bit인 것이다.
- 개발 언어의 기본 data type(int, long 등)의 크기는 표준이 최소 범위만 보장하고, 플랫폼에 따라 달라질 수 있다.
	- ex) long은 64비트 리눅스에서 8byte, 64비트 윈도우에서 4byte
	- 크기가 중요한 경우 고정 폭 타입을 사용해야 한다.
```c
#include <stdint.h>

int32_t a; // 정확히 32비트 정수
int64_t b; // 정확히 64비트 정수
```

## 2.1.3. 멀티 바이트 객체의 주소지정 / 바이트 순서(Big Endian / Little Endian)

- 일반적으로 컴퓨터에서 멀티 바이트 객체는 연속된 바이트에 저장되며, 객체의 주소는 사용된 바이트의 최소 주소로 정한다.
```c
int a;
// &a : 0x100 일 경우
// 4바이트의 a는 0x100 0x101 0x102 0x103의 위치에 저장된다.
```

- 멀티 바이트 데이터의 바이트 오더링
	- Big Endian : MSB를 가장 낮은 메모리 주소에 저장하는 방식
	- Little Endian : MSB를 가장 높은 메모리 주소에 저장하는 방식
		- MSB(Most Significant Byte) : 데이터에서 가장 큰 가중치(자릿수)를 가지는 최상위 바이트
		- zen 아키텍처 (x86-64 ISA)는 Little Endian 방식을 사용함
		- 네트워크 통신에서는 Big Endian 방식을 표준으로 사용함

- 바이트 오더링 예시
	- 네트워크 관습
	- 송신 측 컴퓨터가 내부 표시를 네트워크 표준으로 변경
	- 수신 측 컴퓨터가 네트워크 표준을 자신의 내부 표시방식으로 변환
```c
// 호스트: Little Endian
// 네트워크: Big Endian (표준)

uint32_t x = 0x01020304; // &x = 0x100 (예시 주소)

// 호스트에서의 메모리 배치
/*
- 0x100 : 0x04
- 0x101 : 0x03
- 0x102 : 0x02
- 0x103 : 0x01
*/

// htonl() : Host to Network Long
// host가 Little Endian -> 바이트 순서를 뒤집어 반환
// host가 Big Endian -> 원본 바이트 순서대로 반환
net_val = htonl(x);

/*
net_val의 메모리 배치 (Big Endian 순서)
- 0x200 : 0x01
- 0x201 : 0x02
- 0x202 : 0x03
- 0x203 : 0x04
*/
```

- `show_bytes.c`를 컴파일하고 실행하여 현재 시스템의 프로세서가 사용하는 엔디안(Endianness) 방식을 확인할 수 있다.
	- 로컬 pc가 zen 아키텍처 (x86-64 ISA) - Little Endian 방식을 쓴다는 걸 확인

## 2.1.4. String

- C에서 string은 null(\0) 문자로 종료를 처리한다.
- ASCII, UTF-8 등의 인코딩 규칙에 따라 문자 처리 (GCC UTF-8 지원 내장)
	- UTF-8은 ASCII 인코딩 규칙을 포함한다. (UTF-8 표 참고)
```c
const char* m = "abcde"; // 메모리 data(.rodata)영역에 저장
// %s format specifier는 char pointer를 받는다.
printf("%s\n", m); // printf의 %s 형식 지정자는 null(\0) 등장까지 읽음
size_t n = strlen(m) // 마찬가지로 null(\0) 문자 등장 시 count 종료
```

## 2.1.5. 코드의 표현

- 소스 코드를 컴파일한 결과물의 명령어 집합은 ISA가 결정한다. (타깃 ISA에 맞게 컴파일해야 해당 CPU에서 동작한다.)
- OS에 따라 호출 규약(ABI)과 시스템 콜 규약이 달라 생성되는 기계어 코드가 달라지고, 실행 파일 형식(ELF, PE, Mach-O)도 달라진다. (따라서 ISA뿐 아니라 OS까지 포함한 타깃에 맞게 컴파일해야 한다.)
- 기계어 코드는 일반적으로 컴퓨터와 운영체제들의 여러 가지 조합들 간에 호환성을 갖지 않는다.

## Boolean Algebra / Bit Operation

- XOR (^)
	- 비트 반전(~) 연산을 일부만 할 수 있음
		- ex) x ^ 0xFF : 최하위 바이트만 반전
	- ~x = x ^ 1
	- x = x ^ 0
	- x ^ x = 0
	- XOR swap
		- 일반적인 임시 데이터 저장 공간을 쓰지 않는 swap (극단적 메모리 절약)
		- 성능적 장점 없음
		- `inplace_swap.c` 참고

- 마스크 연산
	- 이진수 표현을 자료구조로 활용해 비트 단위로 값을 켜고(1), 끄고(0), 확인하는 기법
	- 속도 빠름, 메모리 절약, 간결한 코드
	- `bitmask.c` 참고 

- 우측 쉬프트 연산(>>) 최상위 비트가 채워질지, 0이 채워질지 주의하여 사용
